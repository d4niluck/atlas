# Подключение Codex к Atlas

Atlas может предоставлять локальному агенту доступ к выбранным пространствам через `atlas-agent`. Приложение должно быть запущено, а нужные пространства — доступны. Для защищённого пространства может потребоваться сначала открыть его в Atlas. Подключение проверялось на macOS; поддержку новых функций CLI на Ubuntu ещё предстоит проверить.

## 1. Создайте агента и ключ

1. На главном экране Atlas откройте **Настройки агентов → Список агентов**, введите имя и нажмите **Добавить**.
2. Сохраните выданный ключ: Atlas показывает его только один раз. Для каждого агента используйте отдельный ключ.
3. Для нужных пространств включите необходимые права и нажмите **Сохранить изменения**. По умолчанию пространства недоступны агенту. Для поиска необходимо разрешить чтение и соответствующий режим поиска.
4. Сохраните ключ в отдельном обычном файле, доступном только владельцу: права файла `0600`, каталога — `0700`. Передайте агенту путь к файлу, а не содержимое ключа в команде. Не добавляйте ключ в репозиторий, журнал или переписку.

## 2. Установите пример навыка

В репозитории есть готовый пример: [atlas-memory](../skills/atlas-memory/SKILL.md). Скопируйте каталог `skills/atlas-memory` в `~/.codex/skills/atlas-memory` и начните новый чат Codex. Если навык с таким именем уже существует, сначала проверьте его содержимое, чтобы не затереть свои настройки.

Навык рекомендует обращаться к актуальной справке CLI и описывает поиск, чтение, изменение и добавление данных. При использовании нескольких ключей укажите агенту, какой файл использовать.

## 3. Проверьте подключение

После запуска Atlas CLI обычно доступен как `~/.local/bin/atlas-agent`. В командах ниже замените пути и идентификаторы на свои; сам ключ в команду не вставляйте:

```sh
/path/to/atlas-agent --help
/path/to/atlas-agent --key-file /path/to/agent.key workspaces
/path/to/atlas-agent --key-file /path/to/agent.key search WORKSPACE_ID 'тема'
/path/to/atlas-agent --key-file /path/to/agent.key search WORKSPACE_ID 'тема' semantic
```

Список команд, диапазоны выдачи и другие параметры смотрите в `--help`. Для поиска по смыслу нужна загруженная модель и включённый режим в настройках Atlas. Если пространство не отображается, проверьте права агента, доступность пространства и подключение внешнего носителя.

## 4. Доступ из ограниченной среды Codex

В некоторых конфигурациях Codex блокирует локальное соединение с Atlas и CLI сообщает `Operation not permitted`. Агент может повторить разрешённую команду через штатный запрос дополнительного разрешения. Если вы доверяете своему CLI и хотите разрешить его вызовы без повторного подтверждения, можно добавить правило Codex, например в `~/.codex/rules/atlas-agent.rules`:

```python
prefix_rule(
    pattern = ["/absolute/path/to/atlas-agent"],
    decision = "allow",
)
```

Замените путь на **абсолютный путь** к установленному CLI, например `/Users/your-name/.local/bin/atlas-agent` на macOS. Вызывайте его напрямую по этому пути, без подстановок оболочки и объединения с другими командами, чтобы правило совпало. После изменения правила перезапустите Codex. Синтаксис и проверка правила описаны в [документации Codex](https://developers.openai.com/codex/rules/).

Правило разрешает запуск **всех команд этого CLI вне ограниченной среды**, а не только подключение к сокету. Поэтому создавайте его только для доверенного исполняемого файла. Ключ и права Atlas продолжают определять доступ к пространствам; более строгая политика Codex или рабочей среды может переопределить правило. Если разрешение отклонено, агент должен сообщить причину, а не обходить ограничение.
